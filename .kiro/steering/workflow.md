# 需求处理流程（硬性要求）

每次收到用户的需求后，必须严格按以下顺序进行，不可跳步直接改代码：

1. **需求分析**：先阅读相关代码，弄清现状、定位根因，说明问题所在。
2. **需求方案**：给出清晰的修改方案（改哪些文件、怎么改、影响范围、风险）。
3. **等待确认**：把分析和方案呈现给用户，等用户明确确认后，才开始实施。
4. **实施修改**：确认通过后再动手改代码，并按项目规则记录版本更新日志。

例外：纯信息性问答、用户明确要求"直接改"或"不用确认"时，可跳过确认步骤。

补充：涉及前端源码（frontend/src）的改动，实施后需 `npm run build` 重新构建，
产物才会在 http://localhost:8080 生效。
