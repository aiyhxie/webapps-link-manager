# 版本号与更新日志自动记录规则

本项目要求：**每当完成一次涉及代码/功能改动的修改需求后，必须自动记录一条版本更新日志**，
系统版本号会随之自增。这是硬性流程，不可遗漏。

## 唯一真相源

- 版本号的唯一真相源是根目录的 `changelog.json`（最新一条记录的 `version` 即当前版本）。
- `server/config.py` 的 `VERSION` 从 `changelog.json` 自动读取，**不要手动改 VERSION**。

## 完成修改需求后的动作（必做）

当一个修改需求实施完成、并通过验证后，作为收尾步骤执行：

```bash
python3 server/changelog.py "本次变更的中文摘要"
```

- 版本号会自动 patch 位 +1（如 1.0.7 → 1.0.8），无需手动指定。
- 摘要写清本次改了什么，多点用 `；` 分隔，例如：
  `"1. 修复拖拽更新版本写错目录的问题；2. 排序去掉"排序:"标签"`
- 变更类型（security/feature/fix/other）会根据摘要关键词自动判断；
  如需手动指定，追加第二个参数：`python3 server/changelog.py "摘要" security`
- 记录后会自动同步到 `PRD.md` 的「版本更新记录」表格，前端「更新日志」弹窗也会展示。

## 判断是否需要记录

- 需要记录：修复 bug、新增/调整功能、安全加固、影响用户可见行为的改动。
- 不需要记录：纯粹的调研/问答、临时验证脚本、未落地的方案讨论。

## 触发时机

- 一个完整的修改需求 = 一条日志（不要每改一个文件就记一次，避免版本号碎片化）。
- 一次对话里若连续完成多个独立需求，可分别记录多条。
